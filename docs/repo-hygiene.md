# Repo hygiene — what stays local vs what goes to GitHub

One rule: **commit source and declarative config; ignore anything generated, secret, or machine-specific.**

---

## The "regenerable artifact" rule

Three files live in `core/ml/src/main/assets/` but are **not committed**:

1. `model_v1.json` — produced by `python ml-training/train.py`
2. `tessdata/eng.traineddata` — downloaded from `tessdata_fast`
3. (future) LLM weights

The app **works without these**; ML features degrade gracefully (see ADR-0007 and the
Tesseract README). This keeps the repo lean and keeps F-Droid reproducible builds
clean: no opaque binaries in git.

For a "clone and run with all features" experience, follow the bootstrap steps in
[README.md](../README.md#getting-started).

## Secrets that must never be committed

If you ever accidentally stage one of these, **stop and rotate**:

- Release keystore files (`.keystore`, `.jks`, `.p12`, `.pfx`)
- Keystore passwords (`keystore.properties`, `signing.properties`)
- Private keys (`.pem`, `.key`)
- Google service account JSON (`google-services.json`) — we don't use Google services
  so this shouldn't exist, but guard just in case
- Personal passphrases used for `.pvxc` export testing — these are user secrets

Git history remembers. Use `git-filter-repo` to scrub anything you accidentally push
and rotate the credential immediately.

## Verifying a clean working tree

Before every commit:

```bash
git status                    # should list only intended changes
git diff --cached             # double-check
./gradlew spotlessCheck       # catches SPDX header violations
```

Before every release:

```bash
git clean -ndx                # dry-run: show what IS ignored in your tree
apksigner verify --verbose app/build/outputs/apk/release/app-release.apk
apkanalyzer manifest permissions app-release.apk
```
